# V86 預登記（2026-11-15，寫於任何 V86 計算之前）

本輪不跑新策略回測、不掃部位倍率、不連 VPS、不呼叫檢視器 API、不建影子或排程。沒有新獲利假說，不進台帳的假說家族。

## 問題一：固定等比例加大開倉量能否同時通過門檻

**方法（固定路徑代數快篩，不是帳戶回測）**

- 來源：V81 帳戶輸出 `doc/research_results/v81/acct_summary.csv`、`acct_v77_D0/D1_equity_hourly.csv.gz`、`acct_v77_D0/D1_trades.csv`，以及現行原配置的同名檔。先核對 V77 D0 +3,757／最低權益 1,174／2021 −231，D1 +4,132／1,241／−45，現行 D0 +6,026、D1 +6,197。
- 假設：交易集合、進出場時點與價格不變；名目、費用、資金費、未實現損益全部按倍率 k 等比例變動。於是權益路徑 E_k(t) = 1,500 + k·(E(t) − 1,500)，每筆淨利 × k，勝負符號不變。
- 只算兩個倍率，不搜尋：k* = 同情境現行淨利 ÷ V77 淨利（D0、D1 各一個）；另列「最低權益剛好 1,000U」的倍率 k_min = 500 ÷ (1,500 − 最低權益)，只用來說明上限，不當候選。
- 指標（逐項由路徑重算，不以比例近似以外的方式外推）：淨利、逐年、最低權益、最大百分比回撤（對運行高點）、全期逐時市價最大回撤、五年已實現回撤、最差滾動 12 月、最差連敗段、勝率、最高保證金占用與最低可用資金、單筆停損價差預算（3% × k）。
- 預先寫明的判讀：k>0 時逐年符號不變，所以 V77 的 2021 負數在任何正倍率下都還是負，不可能通過「每個完整年度為正」。現行原配置的 2021、2023 同理。結論只能是「固定放大不是已達標候選」。若有人主張熔斷、拒單或資金路徑會在放大後改變年度符號，那是新的路徑相依假說，須另行登記，本輪不做。
- 限制：保證金占用 × k 可能超過可用資金而跳單；熔斷門檻若是固定美元會提早觸發；強平與費用穿價不完全等比例。這些都會改變路徑，快篩不涵蓋。

## 問題二：V85 唯讀工具能否由使用者安全執行

**逐檔審查**：列出所有匯入、網路目的地、HTTP method、API 路徑、檔案讀寫、子程序、例外路徑。

**必修項（審查前已知的弱點）**

1. 簽名時間戳改用伺服器時間差校正，避免 -1021。
2. HTTP 或網路錯誤時只印遮蔽後的訊息（狀態碼與 Binance 錯誤碼），不印網址、簽章或回應全文。
3. 不重試；每個時間窗口完成後寫入檢查點，可中斷後 `--resume` 續跑，已完成窗口不重查。
4. 單一窗口達 1,000 筆上限時二分窗口重查，不靠 fromId。
5. 輸出目錄不得位於任何 git 工作樹內；目錄權限 700、檔案 600；輸出附 SHA256SUMS。
6. 移除讀取 `.env` 的選項：金鑰只從環境變數讀，建議以 `read -rs` 輸入唯讀金鑰，不進 shell 歷史。
7. 新增 `check` 子命令：唯讀讀取使用者自己的 `trades.csv`，與輸出的成交配對，只印去識別摘要（筆數、毫秒延遲、bp 差、欄位是否齊全），不印價格、數量或識別碼。

**離線測試（假回應，不連網）**：允許清單外路徑被拒；只發 GET；載入後 `sys.modules` 不含 binance、executor、strategy、requests；金鑰與簽章不出現在 stdout、stderr、輸出檔；錯誤訊息遮蔽；輸出目錄在 git 工作樹內被拒；1,000 筆截斷時二分；續跑不重查；時間戳用伺服器校正。

**判定標準**：上列測試全過，才說「可交使用者審查」；研究 AI 不執行真實查詢，也不宣稱「已驗證可在 VPS 安全執行」。
