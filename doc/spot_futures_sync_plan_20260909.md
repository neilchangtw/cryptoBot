# ETH 現貨／合約同步突破研究預登記

2026-09-09。使用者目標：固定保證金、槓桿與最大部位，提高扣成本收益及淨勝率。先固定規則，再讀候選結果。

## 資料與規則

沿用凍結合約 1h 資料 17,519 根，2024-09-08 11:00 至 2026-09-08 09:00（台北開盤時間）。補相同區間 Binance ETHUSDT 現貨 1h，約 18 次 API 請求，預估數 MB。沿用既有 funding、mark 與原策略，不刷新合約基準造成不可比較。這是既有歷史資料的追加研究，前後分段不能稱全新 OOS。

L：合約通過原全部進場條件時，現貨當根已收盤 close > 現貨 close.shift(1).rolling(15).max() 才進場；S 用嚴格小於前 15 根最小 close。兩市場各用自己的界線，不比較現貨價與合約界線。相等不算突破。只在原進場時刻檢查，不等待、不延後補單；被拒絕不增加月開單數、不觸發冷卻，後續依完整引擎重算。

- base：原策略。
- both：L/S 都要求現貨同步（主假說）。
- long：只對 L 套用（預先固定的方向診斷）。
- short：只對 S 套用（預先固定的方向診斷）。

同時保存原交易的同步／不同步分桶、L/S、前後期及最近實盤時段。分桶只是描述，正式比較必須含替代交易、占倉、熔斷、冷卻、成本。不得看到不同步較好後反向另選規則。

## 資料稽核與時間因果

公開 GET /api/v3/klines，不讀 API key。檢查原始開／收盤時間、UTC 轉台北、整點連續、無重複缺漏、OHLC 合法、僅已收盤。缺漏立即停止，不以前值或合約價補現貨。前 15 根不足不允許同步進場；原 GK 暖機更長，應驗證不影響基準訊號。保存原始回應、參數、SHA256、請求量及耗時。既有合約 1h/5m 的兩根差異仍屬原基準限制，本研究不用 5m。

同根現貨及合約只可於收盤後使用；歷史資料沒有當時 received_ts，不能證明實盤整點 +10 秒一定已收到兩邊資料。若通過仍須前瞻記錄與延遲檢查，不直接部署。

## 驗證及停止條件

4 規則 × 固定 200U／既有歷史保證金排程 × 每次成交額外 0／2／5bp = 24 組完整狀態回測。費用、funding、1h mark MDD 沿用原帳本；mark MDD 非棒內最大風險。勝率以扣 funding 的 net>0 定義。

報告全期、2026-01-01 前後、2026-06-01 起、L/S、PF、MH 筆數及損益、MDD、最差 30 日、消失贏家／輸家及新增交易。基準須六情境逐欄 parity，對兩個截斷點做指標、已平倉交易及 gate 事件前綴一致測試。合成測試覆蓋兩市場獨立界線、嚴格不等式、前 15 根不含當根、時區／時間錯位及未來資料污染。

基本門檻：固定 200U 在 0／2／5bp 下，全期及前後期淨收益、淨勝率均高於 base；全期 MDD 與最差 30 日惡化不超過 10%；全期受影響交易 >=30，後期受影響交易 >=30。樣本不足標示證據不足，不以百分比掩蓋。

7 日區塊 bootstrap 2000 次，三候選 Holm 校正；歷史重複研究偏誤不能由這次校正完全消除。只有基本經濟及樣本門檻都過者，才進一步六段連續 walk-forward（48h embargo）、10bp、窗口 14/16 穩健性、移除最佳月。全部未過則停止，不擴展指標救結果。任何歷史成功最多 SHADOW，需真正未見資料驗證。
