# V38 預登記：訊號小時逐筆成交能否分辨真假突破（2026-10-29）

**狀態：PLANNED — 資料尚未下載。** 不修改 `strategy.py`、`executor.py`、`.env`；VPS 只跑獨立研究腳本，不重啟機器人。

## 問題

8～10 月 MaxHold 虧損單的 MFE 中位數只有約 0.5%，等於進場後完全沒有延續。K 線層級的進場過濾（V15）、23 特徵 ML（V27）、子 K 站穩（9/8）都無法在進場當下分辨。1h K 線已含整小時主動買量，所以本輪只看 **K 線看不到的「小時內」訂單流結構**。

## 資料與邊界

- 母體：`v38_signal_aggtrades.py` 以現行引擎（固定 200U、貼近實盤、每筆 +$5）重播 2024-11-01 起的進場，每筆只取「訊號棒那一小時」的 Binance USDⓈ-M `aggTrades`。
- 來源（2026-10-29 修訂，特徵與門檻未變）：REST `aggTrades` 以時間或 fromId 查詢皆只限最近 2 天（code -4166），改為只下載有訊號的那些 UTC 日的 data.binance.vision 每日檔，取出訊號小時後立即刪檔，同時只暫存一天。
- 只在 VPS 執行（V37 計畫：不在公司網路／設備下載行情）。原始逐筆不保留，只存 `doc/research_results/v38_signal_aggtrades/features.csv`。
- 所有特徵只用訊號棒收盤前的成交（`T < 收盤`），進場仍在收盤。

## 鎖定特徵（全部依交易方向對齊，L 看買方、S 看賣方）

| 特徵 | 定義 |
|---|---|
| taker_last15 | 最後 15 分鐘順向主動成交量占比 |
| delta_last15 | 最後 15 分鐘（順向－逆向）主動量 ÷ 整小時量 |
| intensity_last15 | 最後 15 分鐘成交筆數 ÷ 前 45 分鐘平均每 15 分鐘筆數 |
| large_share | 名目 ≥ $100k 的 aggTrade 量占比 |
| large_imbalance | 大單（順向－逆向）÷ 大單量 |
| accept_share | 成交在突破界線 B（前 15 根收盤極值）之外的量占比 |
| cross_minute | 首次成交越過 B 的分鐘 |
| post_cross_taker | 越過 B 之後的順向主動量占比 |
| vwap_gap_pct | 收盤相對該小時 VWAP 的順向距離（%） |
| post_cross_adverse_pct | 越過 B 後最大逆向回落（%） |

## 判定門檻（看資料前鎖定）

**第一階段（診斷）**：開發期 = 進場 < 2026-01-01，保留期 = 2026-01-01 起。每個（方向 × 特徵）算開發期 rank-AUC（標籤 = 淨損益 > 0）與 2,000 次標籤洗牌 p 值。通過條件：
1. 開發期 p < 0.05 ÷ 20 = 0.0025（Bonferroni）；
2. 保留期 AUC 與開發期同方向，且 |AUC − 0.5| ≥ 0.05。

全部未過 → **REJECTED**，訂單流方向結案，不再細調特徵。

**第二階段（僅第一階段有通過者）**：以開發期三分位切點擋掉最差三分之一，完整重播（含替代交易；替代交易若缺特徵就補抓）。需同時：開發、保留兩段勝率都 ≥ 現行 +3pp，且各段 PnL ≥ 現行的 90%。通過後也只列 SHADOW，以 2026-10-29 之後的新交易前推，再由使用者決定是否上線。
