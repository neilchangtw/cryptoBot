# 第2輪預登記：H 同商品反向持倉重疊 gate

第1輪G已於round1_diagnostic.json停止：44／14群，沒有計算候選PnL。此輪只選一個方向，不重跑G或A–F。

假說：同一ETH商品已有反向倉位且原規則尚未出場時，反向新倉可能主要帶來抵銷曝險與額外成本；拒絕這種新倉能否提高同風險上限下收益，交由完整狀態驗證。不能因交易較少／曝險較低便聲稱成功。

公式：所有原進場gate滿足後，L另須 `sp_active==False`；S另須 `lp_active==False`。使用當根所有原出場完成後、該方向新進場前的即時狀態。原持倉完全不動，不平移、不合併、不把拒絕訊號排队，也不修改L/S各一倉、每倉4000U、20x的上限設定。

資料只需原引擎持倉狀態，事件及接收時點均由自身交易流程決定，沒有外部新增訊號。歷史基準仍使用原已收盤K線可用假設。缺狀態直接停止，不能把未知當無倉。

直接事件：在0bp原引擎原進場gate真正允許時，當時反向倉位仍active。事先保存的gate與該bar出場後狀態對齊；原breakout_long及short不可能同根同真，因此不會把當根新開反向倉誤算進去。不讀出場理由或終局PnL。群聚沿用24h連結，全期30／後期15群最低門檻。

鄰域（主候選通過才跑）：僅在反向持倉已滿1根／已滿2根時才拒絕新倉。主候選為所有反向active，沒有收益後選擇。其餘時分、成本0／2／5bp、完整狀態、期末倉位、no-op、前綴、六項經濟門檻及進階停止條件全部沿用共同契約。

查重：`eth_dual_strategy.py:run_parallel` 的P3是「v6優先，v6有任一方向持倉時禁止另一個C4策略」，且按equity風險比例決定數量；不是現行V14的同一商品L/S反向抵銷。V23 Path H是BTC跨商品避險，也不是本規則。只檢驗現行固定額L/S真正重疊，不重跑舊跨策略或跨標的避險。原上限保留，但实际最大同時持倉可下降，必須揭露；即使MDD下降，淨收益未達+5%仍淘汰。
